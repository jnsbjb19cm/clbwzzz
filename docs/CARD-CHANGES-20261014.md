## 二、强化（星级）成长：改动前后对照

### 2.1 公式

```
旧：攻击倍率 = P + 0.08 × Q
    生命倍率 = 防御卡 ? P + 0.08×Q + 0.08×V : P + 0.05×Q

新：攻击倍率 = P + 0.08×min(Q,5) + 0.06×max(Q−5,0)
    生命倍率 = 防御卡 ? P + 0.08×min(Q,5) + 0.06×max(Q−5,0) + 0.08×V
                      : P + 0.05×min(Q,5) + 0.04×max(Q−5,0)

   其中 P = 品质倍率、Q = 强化星级、V = 防御卡额外加成星数
```

### 2.2 满强化（15 星）时的实际收益

| 项目 | 改动前 | 改动后 | 变化 |
|---|---|---|---|
| **攻击** 相对 +0 星 | +120%（=0.08×15） | **+100%**（=0.08×5+0.06×10） | −20% |
| **生命（普通卡）** | +75%（=0.05×15） | **+65%**（=0.05×5+0.04×10） | −10% |
| **生命（防御卡）** | +120% + 0.08V | **+100% + 0.08V** | −20% |
| 前 5 星收益 | — | **完全不变** | 无感 |

> 设计意图：**不动星级、不动品质、不动强化成本**，只让"高星段的边际收益"变小，
> 避免出现"一张低品质满强化卡 ≫ 一张高品质没强化卡"。

### 2.3 落地方式（新增可复用的单一来源）

```js
// src/core/constants.js
export function getInstanceStatMultiplier(craftQuality, stars)        // 攻击
export function getInstanceHpMultiplier(craftQuality, stars, defense, defenseBonus)  // 生命
function getStarGrowthBonus(stars, earlyRate, lateRate) {             // 两段式成长
  return earlyRate * Math.min(5, stars) + lateRate * Math.max(0, stars - 5);
}
```
`src/battle/CardStatFormula.js` 改为调用这两个函数（不再各写一份倍率），
`src/systems/CardStrengthenSystem.js` 同步使用。

## 四、今天其它卡牌相关修复

| 问题 | 根因 | 修复 |
|---|---|---|
| **补完全卡后改品质，补的卡消失** | 服务端补卡过滤是 `品质 < 6`，而客户端有 55(战争古树)/118(狂暴法师) 这类品质 6 卡 → 只有本地有 → 一旦同步就被覆盖 | 服务端过滤改为与客户端一致（只排除未开放卡 126） |
| **全库重新补卡** | 上面那条修复后需要让服务端真正拥有这些卡 | 全库补发共 **2595 张**（每号 +6 张）；`#41` 单独补上 55 |
| **品质升阶 / 洗练石报「目标卡牌无效」(400)** | 服务端按**槽位号**取卡并用**实例身份**比对，客户端与服务端卡表顺序不一致时必然对不上 | 操作前**先拉一次服务端卡表**，再**按卡牌身份重新定位槽位** |
| **按 ID 排序后，洗练石点到 A 卡却作用在 B 卡** | 同上（下标错位） | 同上（按身份定位，不再用旧下标） |
| **部分卡攻击动画播到一半回弹 / 抽搐**（如极·寒冰椰子） | ① 校准模块与播放器**各自算一套**攻击时长；② 攻击动画帧号取模后**绕回第 0 帧** | ① 时长统一交给播放器；② 攻击类动画**不再循环**（停在末帧） |
