**入口**：大厅「💎 钻石充值」按钮 → 弹窗

| 入口 | 行为 |

**规则**：
- 选择题：选对给钻石（难度 1→8 / 2→12 / 3→20）

**实现**：

## 三、修复（今日卡牌/背包相关）

### 3.1 补完全卡后改品质，补的卡消失（15:45）
- **根因**：服务端补卡过滤是 `品质 < 6`，而客户端有 `#55 战争古树`/`#118 狂暴法师` 这类品质 6 卡 → 只有本地有 → 任何一次服务端同步就把它们覆盖掉。
- **修复**：服务端过滤改为与客户端一致（只排除未开放卡 `126`）。
- **附带**：全库重新补卡 **2595 张**（每号 +6）；`#41` 单独补上 `55`。

### 3.2 品质升阶 / 洗练石报「目标卡牌无效」400（17:17）
- **根因**：服务端按**槽位号**取卡，并用 `expectedTarget`（卡牌**实例身份**）比对；客户端与服务端卡表顺序不一致时必然对不上（探针已证明：本地顺序 `126,58,75…` vs 服务端 `18,19,20…`）。
- **修复**：操作前**先拉一次服务端卡表**并应用，再**按卡牌身份重新定位槽位**；找不到就提示「卡牌列表已更新，请重新选择，未消耗道具」，**绝不误改别的卡**。

### 3.3 按 ID 排序后，洗练石点到 A 卡却作用在 B 卡（17:17）
- 与 3.2 同源（下标错位），一并修复。

## 四、平衡与数值（22:55）

### 4.1 强化（星级）成长改成两段式

```
旧：攻击倍率 = P + 0.08×Q
新：攻击倍率 = P + 0.08×min(Q,5) + 0.06×max(Q−5,0)
    生命倍率 = 防御卡 ? P + 0.08×min(Q,5) + 0.06×max(Q−5,0) + 0.08×V
                      : P + 0.05×min(Q,5) + 0.04×max(Q−5,0)
```

| 项目 | 改前（15 星） | 改后（15 星） |
|---|---|---|
| 攻击 | +120% | **+100%** |
| 生命（普通） | +75% | **+65%** |
| 生命（防御） | +120% + 0.08V | **+100% + 0.08V** |
| 前 5 星收益 | — | **完全不变** |

- 新增单一来源函数：`getInstanceStatMultiplier` / `getInstanceHpMultiplier` / `getStarGrowthBonus`
- **单卡数值 `card.json` 一行未改**（改的是公式）

### 4.2 统一卡牌数值显示
`BagView`（±20）/ `DeckSelectView`（±10）/ `BattleView`（±10）/ `BattleRoomStabilityPatch`（±10）/ `SmithyView`（−1）/ `CardStatFormula`（±7）
→ 背包 / 卡组 / 铁匠铺 / 战斗房间的显示值与实战值**同源**。
